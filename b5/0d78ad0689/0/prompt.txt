Genuinely useful — and specifically useful in a way most style guides aren't. The thing that made it work: the seven Core Facts were *sufficient to start*. I made the first six or seven decisions (dark canvas, Space Grotesk, square CTAs, green-as-fill-not-text) before loading a single reference file. Most brand docs make you read everything before you can pick a background color.

## What carried the work

**The two-sources split.** Telling me exactly what the live JSON owns versus what only the local refs own meant one fetch, zero ambiguity. And "liatrio.com is dead, never fetch it" is the kind of negative instruction that saves a wasted tool call and a wrong citation.

**Pre-computed contrast ratios.** Having 2.94:1, 5.65:1, 5.39:1, 9.98:1 already in the text meant I could make the print-theme decision (green becomes fill-only on paper) without deriving anything. I still verified all 19 pairs myself, but the skill told me *which* pairs were the risky ones.

**"These are defects, not precedent."** Calling out the two shipped surfaces that break the light-surface rule is a strong pattern. It preempts the exact failure where an agent finds a real Liatrio page doing something and copies it.

**"Name the conflict rather than silently picking a side."** That line directly produced the form-border callout. Without it I'd probably have just fixed it quietly.

## What I had to fill in

1. **The form recipe contradicts the contrast floor, and the skill doesn't know it.** `border: 1px solid #2A3036` is 1.25:1 on the canvas. SKILL.md mandates 3:1 for non-text UI. That belongs in the same defects list as the two light-surface breaks. The nuance worth capturing: decorative card hairlines are arguably out of scope for 1.4.11, but a *control boundary* is in scope. Same token, different verdict by role.

2. **No categorical/data-viz guidance.** "One expressive accent per surface" is right for a landing page and wrong for a 51-item filterable inventory with 5 categories. I derived a scale (bright green → lagoon → violet → lime → primary green) and justified the deviation, but a short "when you need N distinct colors, use this order, always pair with a text label" would remove the guesswork. There's a `dataviz` skill in the harness with nothing linking to it.

3. **No print recipe.** The design-system file says light surfaces are fine for "printable assets" but never says how the dark palette maps to paper. The one that bit me: **`logo_Liatrio_reverse-preferred.svg` prints as an invisible wordmark on white.** Silent failure — flame shows, "liatrio" doesn't. I only caught it by rasterizing the PDF. That swap rule feels like something the skill should own outright.

4. **Report/document surfaces aren't covered.** Every recipe is a marketing component. Sticky section nav, filter panels, dense inventory grids, footnotes — built from general principles.

- `circuit-divider.svg` ships with `preserveAspectRatio="xMidYMid slice"` baked in. Correct for its original full-bleed host, wrong as a fixed-height CSS background — it crops the traces. One line in the asset table would cover it.
- The bundled font is a variable **TTF**: 134KB → 179KB as base64. A woff2 would cut that ~60–70%, which matters for self-contained artifacts, and "use the bundled font, don't call Google Fonts" is your own instruction.
