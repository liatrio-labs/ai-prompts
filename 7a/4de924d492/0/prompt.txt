### [P1] The form specimen models a visually styled but semantically incomplete error state

**Location:**

- Form specimen: `docs/liatrio-design-system-showcase.html:832-845`
- Accessibility claims: `docs/liatrio-design-system-showcase.html:1240-1248`

Observed DOM:

- error input has no `aria-invalid`
- error message has no `id`/`aria-describedby` relationship
- email field uses `type="text"` rather than `type="email"`
- controls have no `name` or `autocomplete`
- no checkbox, disabled, or required state is demonstrated

The message is visible, so this is not strictly color-only, but assistive technology is not told that the field is invalid or which message explains it.

**Impact:** The page is intended to teach implementation. Humans may copy a pattern that looks accessible but is incomplete.

**Fix:** Make the example a complete accessible specimen: `type="email"`, useful `name` and `autocomplete`, `required`, `aria-invalid="true"`, and `aria-describedby` linked to the error message.

### [P2] Focus treatment contradicts the page’s own rule

**Location:**

- Rule: `docs/liatrio-design-system-showcase.html:902-911`
- CSS: `docs/liatrio-design-system-showcase.html:156-158`

Primary, outline, and nav buttons receive the 2px Bright Green outline. However:

- sticky navigation links use the browser’s 1px auto outline
- contents links use the browser’s 1px auto outline
- `.btn-fg` uses the browser’s 1px auto outline
- `.chip:focus-visible` is styled even though chips are non-focusable `<span>` elements

**Fix:** Apply one shared `:focus-visible` rule to every genuinely interactive element and remove unreachable focus styling.

### [P2] Semantic document structure is incomplete

Observed:

- no `<main>` landmark
- no skip link
- heading sequence begins `H1 → H3` because “Contents” is an `<h3>` at `docs/liatrio-design-system-showcase.html:337`
- the document contains an exceptionally long main region: approximately **24,229px** desktop and **41,532px** mobile

**Fix:** Add a skip link and `<main>`, then make Contents an `<h2>` or remove it from the heading outline.

### [P2] Mobile navigation is undersized and poorly discoverable

**Location:** `docs/liatrio-design-system-showcase.html:25-40`

At mobile width:

- nav links are approximately **28px high**
- only the first few sections are visible
- horizontal scrolling has no edge fade, cue, or alternative menu
- no current-section indicator exists despite a 12-section, 40k-pixel page

**Fix:** Increase touch height, add a visible overflow affordance, and expose current-section state. A compact section selector would be proportionate; a new navigation subsystem would not be.

### [P2] Motion specimens animate the layout property `left`

**Location:** `docs/liatrio-design-system-showcase.html:219-227`

All comparison dots continuously animate `left`, forcing layout work. This is particularly unfortunate in a page teaching motion implementation.

**Fix:** Animate `transform: translateX(...)`. Preserve the shared timing comparison and existing reduced-motion behavior.

### [P2] Images lack intrinsic dimensions and below-fold loading policy

All 14 images loaded, but none supplies HTML `width`/`height`, and every image uses default eager loading.

**Impact:** Potential layout shifts and unnecessary initial decode/network work on a very long page.

**Fix:** Add intrinsic dimensions and lazy-load below-fold logo/motif specimens. Keep the topbar logo eager.
